# Convenciones DDL Oracle — Modo `dw-architect-oracle`

Estas convenciones complementan (no reemplazan) las reglas globales de `.bob/rules/`. Fuentes: `docs/IBM_BOB_SDLC_ANALYTICS_TMS_SPEC.md` §3, §5.2 y `docs/Arquitectura-dw-analytics-tms.docx` §4, §6.

## 1. Esquemas y usuarios

| Esquema / Usuario | Rol | Privilegios |
| :--- | :--- | :--- |
| `STG_SRC` | Datos crudos de fuentes | Escritura: `SIM_WRITER` (`INSERT/UPDATE`) |
| `EDW_3FN` | Capa atómica 3FN | No expuesto a Superset |
| `DWH_MART` | Dimensiones conformadas y hechos | `SELECT` para `BI_READER` |
| `BI_SEMANTIC` | Vistas de rol y vistas materializadas | `SELECT` para `BI_READER` |
| `SIM_WRITER` | Usuario del simulador | `INSERT/UPDATE` solo sobre `STG_SRC` |
| `ETL_RUNNER` | Usuario de dbt-oracle | Privilegios exactos a definir en Fase 2 (la spec no los fija) |
| `BI_READER` | Usuario de Superset | `SELECT` solo sobre `BI_SEMANTIC` y `DWH_MART`; sin DML ni DDL; sin acceso a `EDW_3FN` |

## 2. Convenciones de nombres y estructura

- Prefijos: `DIM_` para dimensiones, `FACT_` para hechos, `VW_` para vistas (incluidas las de rol).
- Todo DDL en scripts idempotentes, numerados en `oracle/init/` (`01_` a `05_`), con la cabecera de `.bob/skills/oracle-kimball-ddl-generator/templates/ddl_header_template.sql`.
- `COMMENT ON TABLE` y `COMMENT ON COLUMN` obligatorios en todas las tablas.
- Tablas de `STG_SRC` con columnas de auditoría: `BATCH_ID`, `INGESTED_AT`, `SOURCE_SYSTEM`.
- Índices B-Tree en todas las llaves foráneas de las tablas de hechos, comenzando por `FK_FECHA_*`.
- Compatibilidad SE2: ver `.bob/rules/02-licensing-oracle-guardrails.md` (sin `PARTITION BY`, sin `COMPRESS FOR OLTP`, sin `ENABLE QUERY REWRITE`).

## 3. Patrón de dimensiones conformadas

- Llave subrogada entera: `NUMBER GENERATED BY DEFAULT AS IDENTITY`.
- Toda dimensión incluye la fila `-1` / `DESCONOCIDO`.
- Las 10 dimensiones conformadas: `DIM_FECHA`, `DIM_HORA`, `DIM_VEHICULO`, `DIM_REMOLQUE`, `DIM_OPERADOR`, `DIM_CLIENTE`, `DIM_UBICACION`, `DIM_PRODUCTO_SAT`, `DIM_POLIZA`, `DIM_PERFIL_VIAJE`.
- Dimensión de rol `DIM_UBICACION`: vistas `VW_DIM_UBICACION_ORIGEN`, `VW_DIM_UBICACION_DESTINO`, `VW_DIM_UBICACION_PARADA` en `BI_SEMANTIC`.
- Ninguna FK de un hecho puede ser `NULL`.

## 4. Grano de las tablas de hechos

### 4.1 Con grano definido en el docx (§6.1)

| Hecho | Grano |
| :--- | :--- |
| `FACT_DESPACHO_VIAJE` | Un registro por viaje despachado en TMS. Degenerada: `NUMERO_TALON`. |
| `FACT_EVENTOS_PARADA` | Un registro por parada/hito en el itinerario. Degeneradas: `NUMERO_TALON`, `NUMERO_SECUENCIA`, `UNIDAD_EMBARQUE_UE`. |
| `FACT_LINEAS_CARGA_CARTAPORTE` | Una fila por partida de mercancía amparada en CFDI. Degeneradas: `UUID_CCP`, `NUMERO_TALON`, `UNIDAD_EMBARQUE_UE`. |
| `FACT_SNAPSHOT_FLOTA_DIARIO` | Un registro por vehículo del inventario por día calendario. |

### 4.2 Sin grano declarado en el docx (Matriz de Bus, §4, procesos 5 y 6)

El docx lista para estos procesos las dimensiones y las degeneradas, pero no define el grano. El grano indicado es una **propuesta inferida** de las degeneradas, **pendiente de validación del Data Architect**. No debe tratarse como dato del docx.

| Hecho | Dimensiones (Matriz de Bus) | Degeneradas | Grano propuesto (pendiente de validación) |
| :--- | :--- | :--- | :--- |
| `FACT_FACTURACION_FLETE` (proceso 5, "Facturación Comercial Flete") | Fecha, Vehículo, Operador, Cliente, Ubicación (rol Destino) | `UUID_INGRESO`, `FACTURA_ID` | Un registro por comprobante / factura de ingreso (CFDI de Ingreso 4.0). |
| `FACT_GASTOS_LIQUIDACION` (proceso 6, "Gastos y Liquidación Viaje") | Fecha, Vehículo, Remolque, Operador | `NUMERO_TALON`, `FOLIO_LIQ` | Un registro por concepto liquidado de un viaje (casetas, operador, mantenimiento u otros gastos). |

Nota: el docx §3 y §8 marcan `FACT_FACTURACION_FLETE` como fuente requerida aún no disponible en los datos reales; se cubre con datos simulados (ver `tms-synthetic-data-sim`).
